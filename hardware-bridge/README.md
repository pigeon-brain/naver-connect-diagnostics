# 커넥트 하드웨어 보조 서비스

LineageOS에서 앱이 RGB 밝기 노드에 접근할 수 없을 때 커넥트 콘솔과 진단 앱이 사용하는 로컬 서비스입니다.

1. PowerShell에서 이 폴더의 `build.ps1`을 실행합니다.
2. 콘솔 0.4.3 이상과 진단 앱 0.1.2 이상을 설치합니다.
3. 대상 기기의 ADB를 root로 전환합니다. 무선 연결의 경우 ADB 주소가 달라질 수 있으므로 현재 연결을 확인합니다.
4. `./start-bridge.ps1 -Serial <현재 ADB 연결 ID>`를 실행합니다. 종료하려면 같은 명령에 `-Stop`을 추가합니다.

서비스는 진단 앱과 설치된 콘솔 앱의 UID를 확인하며, 화면·카드 슬롯 RGB 9채널의 밝기와 최대값을 제공합니다. 재부팅하면 서비스가 중지되므로 다시 시작해야 합니다. 실행 로그는 기기의 `/data/system/connect-rgb-bridge/bridge.log`에 있습니다.

## 카드 리더 확인

root ADB가 연결된 상태에서 `python card_probe.py --serial <현재 ADB 연결 ID> firmware`로 모델과 펌웨어를 조회합니다. 마지막 인자를 `ic-status`로 바꾸면 IC 응답의 상태 바이트를 확인합니다. NC1-KIC XR0012에서는 실기 비교로 48=삽입, 49=제거를 확인했습니다. 다른 펌웨어나 응답은 미확인으로 표시합니다.

재부팅 후 UART 장치 파일이 없으면 `--repair-node`를 추가합니다. 이 옵션은 커널에 등록된 ttyS1 장치 번호와 드라이버를 확인한 뒤 누락된 장치 파일을 만듭니다.

## 진단 앱 연결

앱 이름은 `커넥트 진단`이며 패키지는 `local.son.connectdiagnostics`입니다. 0.1.2의 `IC 카드`에서 `상태 조회` 또는 `감지 시작`을 누릅니다. 화면을 벗어나면 반복 조회가 중지됩니다. 앱은 인증된 로컬 소켓으로 삽입 상태만 받습니다. 보조 서비스는 UART의 동시 접근을 막고 읽기 제한시간 뒤 프로세스를 종료합니다.

MSR의 수신 도구는 준비했지만 실제 슬라이드 이벤트는 미검증입니다. NFC 진단 모드 시험에서는 유효한 감지 응답을 확인하지 못했으며, 종료 후 생산 프로토콜의 펌웨어와 IC 상태 응답을 다시 확인했습니다. 리더 부저는 안드로이드 스피커 음소거와 별개입니다. 무음 조건에서는 부저 제어가 검증될 때까지 슬라이드·RF 활성화·리더 모드 전환·리더 재시작을 실행하지 않습니다.
공장 RF 검사 도구는 --allow-reader-sound를 명시하지 않으면 ADB 연결 전에 중단됩니다. 이 옵션은 사용자가 리더 부저 소리를 허용했을 때만 사용합니다. MSR은 분석한 MP25 펌웨어에서 FC34 전송 전에 부저 패턴을 호출하므로 수신만 하는 도구로도 실제 스와이프의 무음을 보장할 수 없습니다. XR0012의 무음 설정은 미확인입니다.
